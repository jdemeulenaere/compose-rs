# 11. Status and known differences

What compose-rs covers of Jetpack Compose today, and where it knowingly differs. The design documents ([02](02-architecture.md) to [09](09-testing.md)) describe how each part works; the decisions log ([decisions.md](decisions.md), indexed by number) records why.

## Platforms

| | Status |
|---|---|
| **Desktop** (macOS, Windows, Linux) | Runs: `application` with `Window`s (or one window with `run_app`), Skia rendering on the CPU raster backend presented with softbuffer, SkParagraph text, input with IME, hover and pointer icons, the system clipboard, AccessKit for screen readers, HiDPI, right-to-left. |
| **Android** (arm64, API 29+) | Runs: `ComposeRsView`, a plain `View` embeddable in Kotlin Compose (`AndroidView`), drawing with the system `Canvas` (hardware-accelerated: the GPU), text by `StaticLayout`, touch, hardware keys, the soft keyboard (its type, action key, capitalization and auto-correction from the field's `KeyboardOptions`, shown and hidden as the content asks), the clipboard ([07](07-platforms.md)). `android/` builds the library and the demo app with Gradle; cargo builds the Rust side. Accessibility through an `AccessibilityNodeProvider`; gradients and path clips drawn as on desktop (D210); graphics layers, clips and shadows are render nodes, as Compose's (shadows the platform's elevation shadows, D522-D525); [12](12-android-performance.md) measures it against Jetpack Compose. |
| **iOS, web** | Not started. |

## Covered

- **Runtime:** the slot table, restart scopes and skipping, `remember`, `key`, state (`mutable_state_of`, `derived_state_of`, state lists), `CompositionLocal`, `SideEffect`, `DisposableEffect`, `LaunchedEffect`, `produce_state`, `remember_updated_state`, coroutine scopes on a UI-thread executor (`delay`, `with_frame_nanos`), blocking work on background threads awaited from tasks (`spawn_background`, as `Dispatchers.IO`), and a manual clock for tests.
- **Composables in Rust:** `#[composable]` functions with call macros for named, default and trailing arguments (documented with their call form), lambdas memoized on their captures and cloning captures where they'd move them (`Text!(name)` in a content block, an `async move` in a click handler, a lazy list's item closures), `ImmutableList` and `#[compose_arg(eq)]` for lists in data models ([03](03-composable-macro.md)).
- **Layout:** `Layout` and measure policies, `Box`, `BoxWithConstraints`, `Row`, `Column`, `Spacer`, arrangements (per axis, custom ones too; no `Arrangement.Absolute`) and alignments, weights, size and padding modifiers (`aspect_ratio`, `wrap_content_*`, `width_in`, `height_in`, `default_min_size`, `Modifier.layout`), `z_index`, `on_size_changed` and `on_globally_positioned`, scrolling, `LazyColumn` and `LazyRow` (lists of items, keys, `fill_parent_max_*`, `reverse_layout`, `user_scroll_enabled`, sticky headers), `LazyVerticalGrid` and `LazyHorizontalGrid` (spans, content types), scrollbars, right-to-left layout.
- **Drawing:** shapes, borders, clips, graphics layers, paths and `ImageVector`, images, arcs, circles and ovals, stroke caps, shadows, `Canvas`, `draw_behind`, `draw_with_content`, `draw_with_cache`, scoped transforms and clips (`rotate`, `scale`, `translate`, `inset`, `clip_rect`, `clip_path`), brushes (linear, radial and sweep gradients: `brush_paint`, `background` with a brush).
- **Text:** `BasicText` (`min_lines`, `on_text_layout` with a `TextLayoutResult`), `SelectionContainer` and `DisableSelection`, selection colors (`LOCAL_TEXT_SELECTION_COLORS`, Material's theme providing its primary color's), `BasicTextField` (selection, IME, undo, Compose Desktop's key mappings, `min_lines` and `max_lines`), `TextStyle` (weight, style, family, letter spacing, decoration, alignment, line height), overflow, `AnnotatedString` spans.
- **Input:** clicks and toggles, `combined_clickable` (double and long clicks), `selectable` and `selectable_group`, `hoverable`, `FocusRequester`, `FocusManager` (clearing the focus, moving it in Tab's order or in two dimensions), `SoftwareKeyboardController`, keyboard options (capitalization, auto-correction, type, action) and actions (the input method's action key too), password fields, pointer events with passes, hover, pointer icons, `pointer_input` with Compose's gesture detectors, `draggable`, keys and focus (Tab order, focus requests, `bring_into_view`), semantics with actions.
- **Windows:** `Popup`, `Dialog`, `TooltipArea`.
- **Platform:** `BackHandler` (back on Android, Escape on desktop; Material's navigation drawer, bottom sheet, menus and dialogs take it), `remember_saveable` with savers (state kept across an Android activity's recreation; lazy list, grid and scroll states saveable), `SaveableStateHolder` (lazy items keep their saveable state when scrolled away), `LOCAL_CONFIGURATION` and `is_system_in_dark_theme`, `WindowInsets` paddings, `decode_image_bytes` and `remember_image_resource` (Skia on desktop, `BitmapFactory` on Android), properties and events between an embedding Kotlin app and its Rust content (how an app calls its own Kotlin, docs/06), `LOCAL_URI_HANDLER`, `LOCAL_CLIPBOARD_MANAGER` and `LOCAL_HAPTIC_FEEDBACK` (`combined_clickable`'s long click vibrates on Android), logging through the `log` crate (logcat on Android, stderr on desktop and in tests).
- **Navigation:** `NavController` (a back stack of typed destinations, saved across the process's death; `navigate`, `pop_up_to`, `launch_single_top`, `pop_back_stack`) and `NavHost` (each entry's saveable state kept while it's on the stack, back pops, optional enter and exit transitions), in `compose-navigation` (D291, D292).
- **Animation:** `Animatable`, tweens, springs, keyframes, repeatables, `animate_*_as_state`, infinite transitions, `AnimatedVisibility`, `Crossfade`, `AnimatedContent`, `update_transition`, `animate_content_size`.
- **Material 3:** the theme (colors, typography, shapes, tonal elevation), `Text`, `Surface` (and its clickable and selectable overloads), buttons (filled, tonal, elevated, outlined, text; with Compose's shape, colors, elevation, border, padding and interaction-source parameters), icon buttons (plain, toggle, filled, tonal, outlined), floating action buttons (small, regular, large, extended), material-icons-core's 49 filled icons, `Checkbox`, `Switch`, `RadioButton`, `Slider`, segmented buttons, `TextField` and `OutlinedTextField` (icons, prefix and suffix, supporting text, line bounds), cards (filled, elevated, outlined), dividers, `ListItem`, top app bars (small, center-aligned, medium, large) with their scroll behaviors (pinned, enter-always, exit-until-collapsed) and `Modifier.nested_scroll`, `BottomAppBar`, `Scaffold` (FAB positions, content insets), `NavigationBar`, `NavigationRail`, `ModalNavigationDrawer` (with `ModalDrawerSheet` and `NavigationDrawerItem`), `ModalBottomSheet`, `SwipeToDismissBox`, the tab rows (primary, secondary, scrollable), `AlertDialog`, `DropdownMenu`, `Snackbar`, progress indicators, `PlainTooltip`, chips and badges.
- **Testing:** `ComposeTestRule` with Compose's finders, actions and assertions, event scripts with transcripts, layout and display-list dumps.

## Known differences

- **No subcomposition.** Content that Compose composes while measuring (lazy items, `BoxWithConstraints`) is composed for what the measurement asks, then the frame recomposes and measures again (up to 16 rounds, D487). `BoxWithConstraints` first composes for a hint of its constraints, so it usually composes once (D142). A lazy list that scrolled composes and measures its next items between frames (prefetch, D156), so the frames reaching them usually compose nothing.
- **`LayoutCoordinates`** is a snapshot handed to `on_globally_positioned`, not a live object (no `localPositionOf`, no parent coordinates), and a graphics layer's property change alone (no layout) doesn't report new coordinates (D172).
- **Ripples** are static state layers (8 % hovered, 10 % pressed or focused), not animated ripples; a `Switch`'s is on its touch target rather than around its thumb.
- **Rendering** is on the CPU: fast at window sizes up to about 1080p (well under a millisecond to render a screen), slower at 4K. A GPU surface is planned (D93).
- **Graphics layers** (D529): any shape clips and casts its shadow, a path outline (a cut corner's, a `GenericShape`'s) its render node's on Android (D1055), concave ones before API 29 and every path before API 33 clipping the node's recording instead, as Compose's; desktop's shadow light is Compose Desktop's, not Android's; a layer after padding has its render node from the group's origin to its far corner (D157), so its offscreen buffer is larger than Compose's by the padding; `LAYERS` lists every layer each frame (103 bytes each, about 1.8 KB a frame more on the feed); an animated inner layer (`background(…).graphics_layer { alpha = … }`) draws its content again each frame, where Compose sets only its properties; a child's move is a translation in its parent's recording, so a list's clip layer is recorded again each scroll frame, where Compose moves its items' layers (`placeWithLayer`); a node drawing its content twice names its inner layer's group twice. As in Compose (parity, not a gap): an outline's alpha is the layer's when the outline is set, not updated when only the alpha changes.
- **Text layout** (D552): the measurers ignore the maximum height, so the ellipsis Compose's `AndroidParagraph` makes at it (`numberOfLinesThatFitMaxHeight`) isn't there, and D550's height rule lays out again a paragraph that comes out the same; a text's intrinsic heights lay it out at the width asked, in a paragraph of their own (D554), as Compose's; text fields keep their own rule (Compose's legacy `TextDelegate.canReuse`); the desktop lays a text out anew on new constraints or style (D550, D555); below API 33 every Android text is a `StaticLayout`, where Compose builds a `BoringLayout` from cached metrics.
- **Drawing** has no `drawText` in a `DrawScope` (nor `TextMeasurer`/`rememberTextMeasurer`: drawing has no access to the platform's text measurer, and paragraphs drawn there would need a per-node cache), no color filters or blend modes, and no `Brush` on `border`.
- **Windows** don't inherit the application's composition locals, and have no position, placement (maximized, minimized, fullscreen), icon, menu bar, tray, or `DialogWindow`; a `Window` can't be composed inside another window's content.
- **Lazy lists** have no `animate_item` (item placement and fade animations); items reuse the composition and nodes of those that left by content type, as Compose's (D430), a reused node's modifier nodes are reset, detached and attached again as Compose's, after the pass's element updates rather than before them (D434, D1153); a reversed list's default arrangement stays `Top` (Compose's becomes `Bottom`, D171); lazy grids have no `reverse_layout`, `user_scroll_enabled` or sticky headers yet, and there are no staggered grids; grids compose item by item and reuse items by content type as lists do (D450); a popup in an item laid out beyond a list's viewport for a focus search shows while it is (D136; a list places only the items in view, D470, D477); accessibility services scroll lists, grids and scrolling containers (D478, D491), but desktop's accessibility doesn't offer scrolling yet, and a scrolling container inside a merging node (a `LazyRow` in a clickable card) offers no scroll actions: the merged tree Android reads leaves merged descendants out, where Compose's virtual tree exposes the unmerged nodes (D496).
- **Text styles** (D1103): the measurers don't draw a style's shadow, baseline shift, geometric transform, font feature settings, locales, draw style, indent, text direction (they take the layout's, or the text's first strong character), line break configuration, hyphens, motion or platform part, nor the `LineHeightStyle` modes other than `Fixed`; a gradient brush paints its colors' average. The model, merges, lerps and savers are Compose's.
- **Text** lays out an `AnnotatedString`'s span styles only: its paragraph styles, links (clickable and styled by state), text-to-speech annotations and bullets are the model (D1104), and there's no `DrawAnnotation` nor `fromHtml`; `TextLayoutResult` has Compose's paragraph queries (D1105) but not its `MultiParagraph` of paragraphs, `getRangeForRect` or placeholders, the fixed measurer doesn't ellipsize at a maximum height, and text fields have no `on_text_layout`.
- **Background work** (`spawn_background`) is a thread pool of its own, not a dispatcher a task switches to: the work is a `Send` closure, and blocking work already running isn't interrupted when its task is cancelled (D231).
- **Material** lacks, among others, dismissible and permanent navigation drawers, `BottomSheetScaffold` and standard bottom sheets, input chips, date and time pickers, search bars, multi-choice segmented buttons, the toggleable `Surface` overload, the content overloads of `ExtendedFloatingActionButton` and `BottomAppBar`, and the bottom app bar's scroll behavior. Elevations snap to a state's value where Compose animates them; a bar's scroll behavior has no fling decay before it settles, and dragging the bar itself doesn't collapse it.
- **Nested scrolling** (D188) finds the connections around a scrollable from the pointer's hit path rather than its layout parents, and has no `dispatcher` for scrolls that don't come from foundation's scrollables (`NestedScrollChain` is there for custom ones); an outer scrollable takes the scroll an inner one leaves, but not the rest of its fling. A wheel over a bottom sheet's content drags the sheet and leaves it where it is (no fling settles it), as Compose's sheet connection does.
- **Bottom sheets** have no drag handle accessibility actions (expand, collapse, dismiss) and no pane title: compose-ui's semantics have no custom actions or pane titles yet.
- **Material's insets parameters** (`window_insets`, `content_window_insets`) take padding, zero by default, though Android reports the window's insets (D183, D222).
- **Values aren't references.** Kotlin passes references; here a lambda clones a capture where it would move it (D158), but at a composable's top level a value given to two calls, or moved into a `LaunchedEffect`'s `async move` before a later use, still needs `.clone()`. State holders (`DrawerState`, `LazyListState`, `SnackbarHostState`, …), `CoroutineScope` and `FocusRequester` are `Copy` handles, as state is, so they never do; made outside a composition, a holder's `new` returns its owner (`Owned<H>`), which must be kept (`*DrawerState::new(…)` gives a handle stale at once), and a holder used after its owner went does nothing, with a warning in debug builds (D240).
- **Saving state:** `remember_saveable` takes no `inputs` (keys that reset it) nor a `key`; a value in a `SaveableStateProvider` is found by its place within the provider, not from the root, and a key composed twice at once panics only in debug builds (D290); lazy items' saveable state is kept for the list's life, as Compose's, so a huge list with saveable item state grows the saved state (Android's `Bundle` limit is about 1 MB); a restored `OwnedState` compares structurally whatever its policy was; the desktop host saves nothing (it's never recreated) (D223).
- **Navigation** (D291): destinations are the app's own type rather than routes, compared with `==` (`launch_single_top` keeps the top only when equal; Navigation Compose compares routes and replaces the arguments); `remember_nav_controller` takes the start destination and the stack never empties; no nested graphs, deep links, dialog destinations, per-entry `ViewModel`s or lifecycles, `saveState`/`restoreState`, pop-specific transitions, nor predictive back; no transition by default (Compose fades); entry ids are random numbers; navigating during composition panics in debug builds (a state write).
- **Platform services** (D281, D283): links open only for `http`, `https`, `mailto` and `tel` unless a subtree widens them (Compose opens any); `ClipboardManager` is plain text (no `AnnotatedString`, no `ClipEntry`, no `LocalClipboard`), and text fields use the host's clipboard even where a subtree provides another `LOCAL_CLIPBOARD_MANAGER`; the services are read from the host when composed, so setting one on a tree after its content composed reaches only what composes later; `combined_clickable` has no `haptic_feedback_enabled` parameter (always on, Compose's default); nothing performs `TextHandleMove` (no touch selection handles yet). There's no `LocalContext`: Kotlin is reached through host events (D282).
- **Window insets** aren't consumed: nested paddings of the same insets add up; sides are physical (no `Start`/`End`), there are no `exclude`, `WindowInsets(left, top, …)` constants, insets animations nor `consumeWindowInsets` (D222). **Back** has no predictive back progress (`PredictiveBackHandler`).
