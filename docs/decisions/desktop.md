# Decision log: Desktop

The desktop host: window, Skia rendering, input and events. Part of the [decision log](../decisions.md): the conventions and the index by number are there. The design documents describe how things work now; each row says what was decided, why, what was rejected, and links to the section with the detail.

| # | Status | Decision | Alternatives rejected | Revert cost |
|---|---|---|---|---|
| <a id="d22"></a>D22 | current | One thread for window, events, composition, layout and drawing ([02](../02-architecture.md#threads)) | a program thread separate from the main thread (needs a frame mailbox and input channel) | medium |
| <a id="d23"></a>D23 | current | Drawing through Skia (`skia-safe`, prebuilt) on desktop, like Compose Desktop's Skiko (user) ([07](../07-platforms.md#desktop-compose-desktop)) | a custom CPU rasterizer then Vello (pure Rust, smaller, but pixels differ from Compose) | medium |
| <a id="d93"></a>D93 | current | (agent) The desktop host renders with Skia's CPU raster backend and presents through `softbuffer`; GPU surfaces (Metal, Vulkan, Direct3D) are a later step behind the same `Renderer` ([07](../07-platforms.md#desktop-compose-desktop)) | GPU surfaces first (a backend per platform before anything is on screen) | low |
| <a id="d113"></a>D113 | current | (agent) On desktop, animation frames are paced at the monitor's refresh interval by the event loop's `WaitUntil` ([07](../07-platforms.md#desktop-compose-desktop)) | a frame as soon as one is asked for (a busy loop with the CPU raster surface, which has no vsync) | low |
| <a id="d134"></a>D134 | current | (agent) Desktop accessibility rebuilds the whole AccessKit tree from the merged semantics tree on a frame that changed anything, only while a screen reader is on; AccessKit node ids are the layout nodes' ids ([07](../07-platforms.md#desktop-compose-desktop)) | incremental updates of the nodes that changed (simpler and correct; the cost is paid only with a screen reader on) | low |
| <a id="d149"></a>D149 | current | (agent) `application`'s content is a composition of its own over a `WindowApplier` (nodes are windows), each `Window` composing its content in its own `UiHost`; window properties and content reach the event loop through a side effect after each application pass; Cmd+Q asks every window's `on_close_request` ([07](../07-platforms.md#desktop-compose-desktop)) | one composition for all windows (a window's tree under the application's: one host's frame and layout for windows of different sizes and densities); `run_app` only (no close requests, one window) | medium |
