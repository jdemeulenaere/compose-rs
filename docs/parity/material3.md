# Material 3 parity ledger

What compose-rs's Material 3 (`crates/compose-material3`) has of Jetpack Compose's, test file by test file and API by API, to drive the work of making it robust and on par with Compose's public API: every public, non-deprecated Material 3 API (experimental ones included), Rust-shaped, with Compose's names and defaults, and Compose's tests adapted as Rust tests (rewritten from each test's scenario, citing the Compose test it covers).

## Scope

- **Reference:** the androidx checkout at `androidx-main/frameworks/support`, commit `d153d87ed76` (material3 1.5.0 alpha, `api/current.txt`).
- **Material 3 proper**, inventoried file by file in section 1:
  - `compose/material3/material3`: its test source sets `src/androidDeviceTest` (148 test files) and `src/androidHostTest` (9). The module has no `commonTest` or `jvmTest`.
  - `compose/material3/material3-ripple`: the ripple node Material 3 draws its ripples with (4 test files).
- **Not inventoried file by file:** the adaptive libraries, window size classes, navigation suite and A2UI (section 5, with a scope recommendation each), and Material 2 (section 6, a summary and a recommendation).
- **Left out:** helper files without `@Test` (`AutoTestFrameClock.kt`, `GoldenCommon.kt`, `MaterialTest.kt`, `MaterialWindowInsetsActivity.kt`), the benchmarks (`compose/material3/benchmark`, `integration-tests/macrobenchmark`: performance, not behaviour), the demos and the catalog.
- **compose-rs:** `crates/compose-material3` at the inventory (`7f744da`): 22 source files (10,476 lines), 37 integration test modules in `crates/compose-material3/tests/suite/` (shortened to `suite/` below) with 204 `#[test]`s, and `tests/review_e_allocations.rs` (1). After milestone 2's ripple, semantics and standard sheets (D1000-D1031): 28 source files (17,602 lines), 75 modules with 837 `#[test]`s; the statuses below are the current ones.

## Main findings

1. **Several compose-rs components follow overloads Compose has deprecated at tip, and lack their replacements.** `Slider(value, …)` (deprecated for `Slider(state: SliderState, …)`; replaced, D1006), `ListItem(headline_content, …)` (deprecated for the `content`-trailing and interactive overloads; replaced, D1004), `TabRow` and `ScrollableTabRow` (deprecated for `PrimaryTabRow`, `SecondaryTabRow`, `PrimaryScrollableTabRow`, `SecondaryScrollableTabRow`; replaced, D1005), `CircularProgressIndicator(progress: f32)`/`LinearProgressIndicator(progress: f32)` (deprecated for `progress: () -> Float`; replaced, D1003), and `rememberModalBottomSheetState` and the `SheetState(skipPartiallyExpanded, …)` constructor (deprecated for `rememberBottomSheetState` and the enabled values, which rest a short sheet half way too; replaced, D1017, D1019). Compose's tests for these components use the new overloads, so the files are `partial`. compose-rs's slider drew Material 3 1.0's slider (a 20 dp round thumb), where Compose's is 1.2+'s (a 4 by 44 dp handle, a 16 dp track with gaps and stop indicators); it is the tip's now (D1006).
2. **About half of Compose's Material 3 tests wait on a missing component or feature**, most of them stable, not experimental: the date and time pickers (240 tests), the expressive components (floating toolbar, button group, toggle and split buttons, short navigation bar, wide navigation rail, FAB menu, loading and wavy indicators, interactive list items, app bar rows: ~450 tests), search bars, carousel, bottom sheet scaffold, exposed dropdown menu, tooltip box, pull to refresh. Several need work outside Material 3 first: a pager and snapping in foundation (carousel, scroll field), `TextFieldState` text fields (secure text field, the state overloads), alignment lines (baseline tests throughout), richer semantics (pane titles, custom and dismiss actions, live regions), an interaction stream (ripples, pressed shapes), a port of `androidx.graphics.shapes` (loading indicator, material shapes), predictive back, and lookahead (a handful of tests).
3. **The test harness needs a small layer of helpers before porting at scale**, and porting will surface real differences. compose-test has no bounds assertions (`assertWidthIsEqualTo`, touch bounds), no touch-gesture DSL (`swipeUp`), no matchers for selection, toggle or range info, no way to emit interactions into a `MutableInteractionSource`, and no pixel capture in the material crate's tests (section 4). Suspected differences found while reading (section 4, "Suspected differences"): NaN progress reports NaN where Compose reports 0; `surface_color_at_elevation` tints with `primary` where Compose uses `surface_tint`; `MaterialTheme` doesn't theme the text selection colors; `remember_modal_bottom_sheet_state` and `remember_swipe_to_dismiss_box_state` are plain `remember`s where Compose's are saveable.

## How to read the statuses

- `covered`: compose-rs tests already exercise the file's scenarios; the notes cite them and say what isn't covered.
- `port`: the feature exists in compose-rs; adapt the tests (the notes cite any existing coverage).
- `partial`: some of it exists; the notes say what's missing and roughly how many tests port today.
- `feature:<name>`: needs the missing feature of that name in section 3.
- `n/a: <reason>`: an adapted test wouldn't make compose-rs more robust (internal Compose helpers, Android-View plumbing).

Screenshot tests (`*ScreenshotTest.kt`) compare against Android goldens, which compose-rs can't match pixel for pixel. Every screenshot file's scenarios are listed with a status as if they were behaviour tests: rewrite each as layout assertions (sizes, positions), display-list assertions (fill colors, strokes, shadows, layers: `ComposeTestRule::dump_display_list`, `UiHost::display_list`), or semantics assertions; where a test really needs pixels, render through compose-skia's `RasterRenderer` (`pixels`, `pixel(x, y)`), as `crates/compose-skia/tests/suite/skia.rs` does.

## 2. The public API compose-rs lacks or only partly has

From `compose/material3/material3/api/current.txt` (`restricted_current.txt` is identical at this commit: nothing is restricted-only), every public, non-deprecated API compose-rs lacks or has only in part, grouped by component. Experimental APIs are marked **[exp]** (`@ExperimentalMaterial3Api`) or **[exp-expressive]** (`@ExperimentalMaterial3ExpressiveApi`); everything unmarked is stable. Names are Compose's; the Rust names follow compose-rs's conventions (snake_case functions and fields, `SCREAMING_CASE` constants, `…Defaults::…` associated functions, struct update syntax for colors, D180). "Rust-shaped" differences that are deliberate (no overloads: `ClickableSurface`, `IndeterminateCircularProgressIndicator`, `AnnotatedText`; `Option` for nullable lambdas) aren't listed as gaps.

### Theme

- **`MaterialTheme`**: `MaterialTheme.Values` is `MaterialThemeValues`, read with `MaterialTheme::values()` (compose-rs keeps the theme in three locals, so there's no `LocalMaterialTheme` object, D1008); `MaterialExpressiveTheme` is there.
- **Dynamic color** (Android): `dynamicLightColorScheme(context)`, `dynamicDarkColorScheme(context)`.
- **`ColorScheme`, `Typography`, `Shapes`**: complete (the fixed roles, `expressive_light_color_scheme`, `LOCAL_TONAL_ELEVATION_ENABLED`, `content_color_for`, the emphasized styles, `Typography::from_font_family`, the increased shapes and `ShapeDefaults`, D1008).
- **Text**: `Text`'s `auto_size` (`TextAutoSize`) and `ColorProducer` overloads, `inline_content` for annotated text.
- **Interactive size**: `MinimumInteractiveTopAlignmentLine`, `MinimumInteractiveLeftAlignmentLine` (dep:alignment-lines; `LOCAL_MINIMUM_INTERACTIVE_COMPONENT_SIZE` is done).
- **Ripple**: `ripple(bounded, radius, color)` (an `Indication`), `RippleConfiguration` (color, `RippleAlpha`, `focus`: `Focus.Opacity`/`Focus.InsetRing`), `LocalRippleConfiguration`, `RippleThemeConfiguration`, `LocalRippleThemeConfiguration`, `RippleDefaults`. compose-ui's `Indication` is a static state layer (color and an optional radius).
- **`MaterialTransitions`** (`scrimColor`, `FadeThrough.transform()`/`predictiveBackTransform`, `HorizontalSharedAxis.forwardTransform()`/`backwardTransform()`/`predictiveBackTransform`).
- **`ComposeMaterial3Flags`** [exp]: 9 behaviour flags. Only `isPrecisionPointerComponentSizingEnabled` changes public behaviour worth porting (feature:precision-pointer); the others gate Compose's own bug fixes.

### Buttons

- **`Button`, `ElevatedButton`, `FilledTonalButton`, `OutlinedButton`, `TextButton`**: the `shapes: ButtonShapes` overloads (a shape and a pressed shape, animated); `ButtonShapes`; `ButtonDefaults`' size tokens (`ExtraSmallContainerHeight`, `MediumContainerHeight`, `LargeContainerHeight`, `ExtraLargeContainerHeight` and their content paddings, icon sizes and spacings), `contentPaddingFor`, `iconSizeFor`, `iconSpacingFor`, `textStyleFor`, `shapesFor`, `shapes()`, `squareShape`, `pressedShape` and the per-size pressed shapes.
- **Toggle buttons**: `ToggleButton`, `ElevatedToggleButton`, `FilledTonalToggleButton`, `OutlinedToggleButton`; `ToggleButtonDefaults` (and the elevated, tonal and outlined ones), `ToggleButtonColors`, `ToggleButtonShapes`, `ToggleButtonElevation`, `ToggleButtonSize`.
- **`ButtonGroup`**, `ButtonGroupScope` (`clickableItem`, `toggleableItem`, `customItem`, `Modifier.animateWidth`, `weight`, `align`), `ButtonGroupMenuState`, `ButtonGroupDefaults` (connected shapes, `OverflowIndicator`).
- **`SplitButtonLayout`**, `SplitButtonDefaults` (leading/trailing buttons of each kind, sizes, inner corner sizes), `SplitButtonShapes`.
- **Icon buttons**: the `shapes: IconButtonShapes`/`IconToggleButtonShapes` overloads; `IconButtonDefaults`' sizes (`extraSmallContainerSize(widthOption)` … `extraLargeContainerSize`, `IconButtonWidthOption` Narrow/Uniform/Wide), icon sizes, round/square/pressed/selected shapes, vibrant colors (`iconButtonVibrantColors`, …), `toggleableShapes`. The three toggle variants, their colors and borders and `shape` on `IconButton`/`IconToggleButton` are there (D1010).
- **FABs**: `MediumFloatingActionButton`; `SmallExtendedFloatingActionButton`, `MediumExtendedFloatingActionButton`, `LargeExtendedFloatingActionButton` (both the text-and-icon and the content overloads); `ExtendedFloatingActionButton`'s content overload; `Modifier.animateFloatingActionButton(visible, alignment, …)`; `FloatingActionButtonDefaults`' medium and extended shapes and icon sizes; `FabPosition.EndOverlay`.
- **FAB menu**: `FloatingActionButtonMenu`, `FloatingActionButtonMenuItem`, `ToggleFloatingActionButton`, `FloatingActionButtonMenuScope`, `ToggleFloatingActionButtonScope`, `ToggleFloatingActionButtonDefaults`.

### Selection controls

- **`Checkbox`**: complete (D1009): `TriStateCheckbox`, the strokes as `checkmark_stroke`/`outline_stroke` parameters, `interaction_source`, every `CheckboxColors` field, `CheckboxDefaults::STROKE_WIDTH` and the six-color `colors` overload as `colors_with`.
- **`Switch`**: complete (D1012): `thumb_content`, `interaction_source`, every `SwitchColors` field, `SwitchDefaults::ICON_SIZE`.
- **`RadioButton`**: `interaction_source`.
- **Sliders**: `RangeSlider` and `RangeSliderState`, `rememberRangeSliderState`; `VerticalSlider` (and `SliderState`'s `orientation`, `reverseVerticalDirection`); `SliderDefaults.CenteredTrack`; `SliderState`'s `onValueChange` and `onValueChangeFinished` properties, `drag`/`dispatchRawDelta` (`DraggableState`). `Slider(state, …)`, `SliderState`, `remember_slider_state`, `SliderDefaults.Thumb`/`Track` (both overloads)/`drawStopIndicator`, `TickSize` and `TrackStopIndicatorSize` are there (D1006); the deprecated value overload is gone.
- **Segmented buttons**: complete (D1013; the checkable overload is `CheckableSegmentedButton`), but `SegmentedButtonDefaults.Icon`'s `activeContent`/`inactiveContent` and its animations (the check shows at once).

### Chips

`InputChip` (with `avatar`), `ElevatedAssistChip`, `ElevatedFilterChip`, `ElevatedSuggestionChip`; on every chip the `shape`, `colors`, `elevation`, `border`, `content_padding`, `horizontal_arrangement`, `interaction_source` parameters and the `shapes: ChipShapes` overloads; `ChipColors`, `ChipElevation`, `SelectableChipColors`, `SelectableChipElevation`, `ChipShapes` as public types; `AssistChipDefaults`, `FilterChipDefaults`, `InputChipDefaults`, `SuggestionChipDefaults` (colors, elevations, borders, `Height`, spacings, tonal colors).

### Cards, surfaces, dividers, icons

- **`Surface`**: complete (the toggleable overload is `ToggleableSurface`, D1010).
- **Dividers**: complete (D1015).
- **`Icon`**: the `ImageBitmap` and `Painter` overloads (and the `ColorProducer` tint one).

### Lists

- **`ListItem`**: **`SegmentedListItem`** (4 overloads); `on_long_click_label` (no click labels in compose-rs's semantics). The tip's `ListItem` overloads are done (`ListItem`, `ClickableListItem`, `SelectableListItem`, `ToggleableListItem`, D1004).

### Menus

- **`DropdownMenuItem`**: the expressive overload with `shape`, `supporting_text`, `trailing_content` (the stable menu is complete, D1016).
- **Expressive menus**: `DropdownMenuGroup`, `DropdownMenuPopup`, `SelectableDropdownMenuItem`, `CheckableDropdownMenuItem`; `MenuDefaults`'s expressive values (group and item shapes, `selectableItemColors`, vibrant colors, `DropdownMenuGroupLabel`, `DropdownMenuItemTrailingLabel`, the selectable paddings, `rememberDropdownMenuPopupPositionProvider`), `MenuItemColors`'s container colors, `SelectableMenuItemColors`, `MenuItemShapes`, `MenuGroupShapes`, `MenuAnchorPosition`, `MenuPositionScope`, `DropdownMenuPopupPositionProvider`.
- **Exposed dropdown menus**: `ExposedDropdownMenuBox`, `ExposedDropdownMenuBoxScope` (`Modifier.menuAnchor(type, enabled)`, `exposedDropdownSize`, `ExposedDropdownMenu`), `ExposedDropdownMenuAnchorType`, `ExposedDropdownMenuDefaults` (`TrailingIcon`, `textFieldColors`, `outlinedTextFieldColors`, `ItemContentPadding`).

### Dialogs, sheets, scrims

- **Dialogs**: `DatePickerDialog`, `TimePickerDialog`, `VibrantTimePickerDialog` (with their pickers). `BasicAlertDialog`, `AlertDialog`'s styling parameters and `AlertDialogDefaults` are there (D1011).
- **`ModalBottomSheet`** [exp]: `ModalBottomSheetProperties.secure_policy` (Android); the drag handle's tooltip; `BottomSheetDefaults.HiddenShape`; the sheet's vertical scale while a spring overshoots its expanded anchor (`verticalScaleUp`, `verticalScaleDown`), which `BottomSheetScaffold`'s and `BottomSheet`'s lack too. The tip's state API is done (D1017).
- **`VerticalDragHandle`**, `VerticalDragHandleDefaults`, `DragHandleColors`, `DragHandleShapes`, `DragHandleSizes`.

### Navigation

- **`NavigationBar`**: `window_insets`.
- **Drawers**: `DismissibleNavigationDrawer`, `DismissibleDrawerSheet`, `PermanentNavigationDrawer`, `PermanentDrawerSheet` (and the sheets' `drawer_state` overloads); `DrawerDefaults.standardContainerColor`, `DismissibleDrawerElevation`, `PermanentDrawerElevation`; `NavigationDrawerItemColors`' icon and badge colors, `NavigationDrawerItemDefaults.ItemPadding`.
- **`ShortNavigationBar`**, `ShortNavigationBarItem`, `ShortNavigationBarArrangement`, `ShortNavigationBarDefaults`, `ShortNavigationBarItemDefaults`, `NavigationItemColors`, `NavigationItemIconPosition`.
- **`WideNavigationRail`**, `ModalWideNavigationRail`, `WideNavigationRailItem`, `WideNavigationRailState`, `rememberWideNavigationRailState`, `WideNavigationRailValue`, `WideNavigationRailColors`, `WideNavigationRailDefaults`, `WideNavigationRailItemDefaults`, `ModalWideNavigationRailProperties`.

### App bars and toolbars

- **Top app bars**: the `subtitle` and `title_horizontal_alignment` overloads of `TopAppBar`; `content_padding` on `TopAppBar` and `CenterAlignedTopAppBar`; **`MediumFlexibleTopAppBar`**, **`LargeFlexibleTopAppBar`**, **`TwoRowsTopAppBar`**; `TopAppBarColors.subtitle_content_color`; the flexible heights in `TopAppBarDefaults`; the scroll behaviors' `state`, `can_scroll`, `snap_animation_spec`, `fling_animation_spec` parameters (compose-rs's take no arguments, D186) and the `pinnedScrollBehavior(scrollableState, …)`/`enterAlwaysScrollBehavior(scrollableState, …)` overloads driven by a `ScrollableState`; `TopAppBarState.Saver`.
- **Bottom app bars**: `BottomAppBar`'s content overload and `scroll_behavior`; **`FlexibleBottomAppBar`**; `BottomAppBarState`, `rememberBottomAppBarState`, `BottomAppBarScrollBehavior`, `BottomAppBarDefaults.exitAlwaysScrollBehavior`, the flexible paddings and arrangements.

**Text measures differ.** compose-test measures text with `FixedTextMeasurer` (a fixed advance per character, not Roboto), so expectations that depend on a text's width or line count (chip widths, two-line snackbars, long labels wrapping) must be computed from the measured text's bounds, or use the Skia measurer as `crates/compose-skia/tests/suite/skia.rs` (the_test_rule_runs_with_the_skia_measurer) does. Compose's tests use real fonts at the device's density.

**Icons.** compose-rs has material-icons-core's 49 filled icons (`icons::filled::*`). Compose's tests also use `Icons.Outlined.*` and `Icons.AutoMirrored.Filled.*`; any icon of the same size works for layout tests.

**Not portable.** Android-only plumbing: secure-window flags (`ModalBottomSheetDialogTest.dialog_securePolicy_setsWindowFlag`), `AccessibilityManager` recommended timeouts (`SnackbarHostTest.snackbarDuration_toMillis_*`), `RippleContainer`/`RippleHostView`, Compose's internal `ComponentStyle` API (`withStyle` screenshots, `cardStyle_*`), motion frame-of-reference tags.

### Suspected differences from Compose

Found while reading compose-rs against Compose; each names the Compose test that would catch it.

1. **NaN progress** (fixed). `progress_semantics` and the drawings clamped with `f32::clamp`, which keeps NaN, so a NaN progress reported NaN in `ProgressBarRangeInfo` and drew a NaN sweep; Compose reports 0 (`ProgressIndicatorTest.determinateLinearProgressIndicator_NaNProgress`, `determinateCircularProgressIndicator_NaNProgress`, ported in `suite/progress_indicator.rs`). The indicators now report and draw a NaN progress as 0.
2. **Tonal elevation's tint** (fixed). `ColorScheme::surface_color_at_elevation` composited `primary` over the surface; Compose uses `surfaceTint` (`ColorScheme.kt`). Same with the baseline schemes (where they're equal), wrong with a custom `surface_tint` (`SurfaceTest.tonalElevationColorIsSetOnElevatedSurfaceColor`, adapted with a custom tint in `suite/surface.rs`).
3. **Text selection colors** (fixed). `MaterialTheme` didn't provide selection colors: selections highlighted in foundation's 40 % #4286F4, where Compose's `MaterialTheme` provides `rememberTextSelectionColors(colorScheme)` (the primary color, its highlight at 40 %) (`TextSelectionColorsScreenshotTest`, `OutlinedTextFieldTest.testOutlinedTextField_selectionColors_areCustomizable`, `TextFieldTest.testTextField_selectionColors_areCustomizable`). Foundation now has `LOCAL_TEXT_SELECTION_COLORS`, `MaterialTheme` provides the primary color's and the fields their `TextFieldColors::text_selection_colors`; the tests are ported in `suite/text_selection_colors.rs`.
4. **Unsaved sheet and swipe states** (fixed). `remember_modal_bottom_sheet_state` and `remember_swipe_to_dismiss_box_state` were plain `remember`s; Compose's are `rememberSaveable`s, so an expanded sheet or a dismissed item comes back as it was after an activity's recreation or a `NavHost` round trip (`ModalBottomSheetTest.modalBottomSheet_stateRestoration_preservesExpandedState`, `SwipeToDismissTest.test_stateSavedAndRestored`). `remember_modal_bottom_sheet_state` also lacked `confirm_value_change`. Both are saveable now (`suite/modal_bottom_sheet.rs`, `suite/swipe_to_dismiss.rs`), and the sheet shows on entering only when hidden, as Compose's restoration fix.
5. **The slider's look and API** (fixed, D1006). compose-rs's `Slider` was Material 3 1.0's (a 20 dp round thumb, a thin track) and the deprecated value overload; Compose's is 1.2+'s (a 4 by 44 dp handle that narrows while pressed, a 16 dp track with a gap around the thumb and stop indicators) on a `SliderState` (`SliderScreenshotTest`, `SliderTest`). It is the tip's now, its keys too (page up and down, no up and down on a horizontal slider, the arrows mirrored right to left: `SlideUsingKeysTest`), and its semantics node 10 dp wider on each side (D1007).
6. **Progress indicators' 1.4 drawing** (fixed, D1003). No stop indicator on the linear track and no gap or track on the circular ones (D572 left them out); the indeterminate ones animated as Material 3 1.0's. All are the tip's now (`ProgressIndicatorScreenshotTest.linearProgressIndicator_lightTheme_determinate`, `circularProgressIndicator_lightTheme_determinate`).
7. **Drawer state without confirmation** (fixed, D1002). `DrawerState::new` took no `confirm_state_change`, so an app couldn't refuse a swipe (`ModalNavigationDrawerTest.navigationDrawer_confirmStateChangeRespect`).
8. **Title baselines.** Top app bar titles are placed with their baseline taken at 80 % of the title's height (D186), not the real first baseline (`AppBarTest.smallTopAppBar_default_positioning`, `centerAlignedTopAppBar_default_positioning`, `mediumTopAppBar_expanded_positioning`, which compare baselines).
9. **Intrinsics** (fixed, D1200, D1207). They were approximated by measuring once (D137); compose-ui's are Compose's now, the layouts with Compose's overrides have them, and those sizing to unbounded constraints follow Compose's measure. `AppBarTest`'s, `NavigationBarTest`'s, the text fields' and `InteractiveListTest`'s intrinsics tests are ported (`suite/intrinsics.rs`); `ListItemTest`'s are the deprecated `headlineContent` overload's (n/a, D1004). The segmented buttons' content answers its own intrinsics (its label's move isn't started by them). `ChipTest.intrinsicSize_filterChip` is still to port.
10. **Snackbar durations ignore accessibility.** Compose lengthens them by the accessibility manager's recommended timeout (`SnackbarHostTest.snackbarDuration_toMillis_nonNullAccessibilityManager`); compose-rs has no such hook (Android could ask `AccessibilityManager.getRecommendedTimeoutMillis` through the bridge).
11. **Insets** (fixed, D1359). The insets parameters were `PaddingValues`, zero by default, so bars, rails, drawers and Scaffold didn't apply the system bars on Android as Compose's do (`MaterialComponentsInsetSupportTest`).
12. **Menu offsets in pixels** (fixed). `DropdownMenu`'s `offset` was an `IntOffset`; Compose's is a `DpOffset`, so the same offset moves the menu by a different distance at any density but 1 (`MenuPositionTest.menuPosition_horizontal_anchorAlignment_withOffset`, ported in `suite/menu_position.rs`). It is a `DpOffset` now (compose-ui has `DpOffset`).
13. **Ripples are static.** State layers at 8 % (hovered) and 10 % (pressed, focused), no ripple animation, no drag state, no inset focus rings (docs/11; `RippleTest`, the 21 `*_insetFocusRings` screenshot scenarios).
14. **Run-time content descriptions** (fixed, D1022). `Icon`'s `content_description` was an `Option<&'static str>`, so a description built at run time ("3 new messages") couldn't be given; Compose takes any `String?`. `Icon`, `Scrim` and foundation's `Image` take `Option<impl Into<SharedString>>` now (`suite/content_description.rs`).
15. **Segmented button borders** (fixed, D1013). compose-rs laid the segmented row out without Compose's z-index (D187), so a selected segment's border could be drawn under its neighbour's (`SegmentedButtonScreenshotTest.stroke_zIndex`). The buttons take Compose's `interactionZIndex` now. Also fixed: a button without an icon was narrower than Compose's, which keeps the icon's room and moves the label back by half of it (`SegmentedButtonTest.segmentedButton_Sizing`), and the unchecked container is transparent and the disabled outline the outline color at 12 %, the tip's tokens.
16. **Menus without their animation or icon colors** (fixed, D1016). `DropdownMenu` appeared and left at once, where Compose's grows in from 0.8 of its size and fades (and out again) from its anchor's side (`MenuTest.menu_canBeTriggered` steps through it); its items' icons were in the on-surface color, Compose's in its variant (`MenuScreenshotTest`), and a trailing icon sat at the item's end instead of the start of its 24 dp slot (`MenuTest.dropdownMenuItem_noLeadingIcon_trailingIconPosition`). The menu's 280 dp maximum also clamped content that isn't an item.
17. **Bottom sheets at 1.3's behaviour** (fixed, D1017). A sheet shorter than half the window had no partially expanded state and every sheet moved on 300 ms tweens; the tip's default state rests any sheet half its height up and animates on the motion scheme's springs (`ModalBottomSheetTest.modalBottomSheet_shortSheet_partiallyExpandedAtHalfContentHeight`). An empty sheet showed itself (Compose's stays hidden until shown, without moving: `modalBottomSheet_emptySheet_expandDoesNotAnimate`), and a state whose anchor went stayed there (`SheetStateTest` reconciliation tests).
18. **A surface's inset ring in one node** (recorded). Compose's `Surface` puts the ring on a separate `indication` outside `.surface()`, with `enableFocusIndication = !insetRing` on the clickable's; compose-rs draws both from the clickable's node, inside the clip: the same pixels but for antialiasing at the edge (`components.rs`, `ButtonScreenshotTest`'s ring goldens wouldn't see it through the display list).
19. **`BottomSheet`'s node takes all the space it's given** (recorded). Compose's is the sheet's size, moved by an offset; compose-rs's `SheetLayout` fills its parent and places the sheet in it, so a sibling after it in a `Column` lands elsewhere (`sheet.rs`; no Compose test has a sibling there).
20. **`Modifier.indication` reads locals where it's made** (recorded, D1025). Made outside a `LOCAL_CONTENT_COLOR` provider and used inside it, its ripple doesn't see the provider; Compose's does, and so does a clickable's here. MN-8's node-level locals remove the difference.
21. **Selections that don't animate** (recorded, D1031). The motion scheme is what these wait on no longer, but they don't animate yet: a navigation bar's and rail's item (Compose: its icon's and label's colors and its indicator's alpha on the default effects spec, its indicator's width on the fast spatial one), a list item's colors, shapes and elevation (the default effects and fast spatial specs), a text field's colors and indicator (the fast effects and spatial specs, the placeholder's opacity), a filter chip's icon (the effects and spatial specs). Each would be a test of its time in `suite/motion_scheme.rs`.

**Recommendations** (the user decides):

- **material3-window-size-class: in scope, S.** Tiny, pure breakpoint logic plus the window's size (the hosts know it; `LOCAL_CONFIGURATION` carries it); its 14 common tests are pure. It is experimental and Compose now steers apps to `androidx.window`'s `WindowSizeClass` through `currentWindowAdaptiveInfo`, so port it as is and don't build on it.
- **adaptive (`WindowAdaptiveInfo`): in scope later, S-M**, as the base of the navigation suite. Window size is easy; posture and hinges need Android's `WindowLayoutInfo` through the bridge (desktop: always flat).
- **material3-adaptive-navigation-suite: in scope after the Material 3 navigation components, M.** It's small and composes `NavigationBar`, `NavigationRail`, `ShortNavigationBar`, `WideNavigationRail` and the drawers, which this ledger already asks for.
- **adaptive-layout and adaptive-navigation: out of scope for now (L-XL).** Large, mostly experimental, and its pane motion leans on lookahead and approach layouts (dep:lookahead) and predictive back. Revisit after Material 3 parity.
- **adaptive-navigation3: out of scope.** It targets Navigation 3's scene API, which compose-rs's `compose-navigation` doesn't model.
- **material3-a2ui: out of scope.** A quarantined catalog for the A2UI protocol, not Material 3 itself.
- **material3-ripple: in scope, inside material3** (section 1 and feature:ripple). **material-ripple** (`compose/material/material-ripple`, 5 test files with 27 tests, plus a benchmark): Material 3 uses only its `RippleAlpha` type (in `RippleConfiguration`); the rest of its API (`rememberRipple`, `RippleTheme`) is deprecated. Recreate `RippleAlpha` in material3 and leave the library out.

## 6. Material 2

`compose/material/material` is the older Material Design library: separate from Material 3, still published and not deprecated as a whole. compose-rs has none of it.

- **Size:** 79 test files with **1,097 `@Test` methods** (device and host tests), 221 of them in 19 `*ScreenshotTest.kt` files. Its `api/current.txt` has 127 classes (118 not deprecated), 851 members, 117 `@Deprecated` entries, and **55 distinct public, non-deprecated composables**: `MaterialTheme`, `Text`, `ProvideTextStyle`, `Surface`, `Button`, `OutlinedButton`, `TextButton`, `IconButton`, `IconToggleButton`, `FloatingActionButton`, `ExtendedFloatingActionButton`, `Card`, `Checkbox`, `TriStateCheckbox`, `RadioButton`, `Switch`, `Slider`, `RangeSlider`, `TextField`, `OutlinedTextField`, `SecureTextField`, `OutlinedSecureTextField`, `ExposedDropdownMenuBox`, `DropdownMenu`, `DropdownMenuItem`, `AlertDialog`, `Snackbar`, `SnackbarHost`, `Scaffold`, `BottomSheetScaffold`, `BackdropScaffold`, `ModalBottomSheetLayout`, `ModalDrawer`, `BottomDrawer`, `TopAppBar`, `BottomAppBar`, `BottomNavigation`, `BottomNavigationItem`, `NavigationRail`, `NavigationRailItem`, `TabRow`, `ScrollableTabRow`, `Tab`, `LeadingIconTab`, `Chip`, `FilterChip`, `Badge`, `BadgedBox`, `ListItem`, `Divider`, `Icon`, `CircularProgressIndicator`, `LinearProgressIndicator`, `SwipeToDismiss`, `PullRefreshIndicator` (with `Modifier.pullRefresh`), plus `Colors`, `Typography`, `Shapes`, `ContentAlpha`, `ElevationOverlay`, and its own swipeable and anchored-draggable states.
- **What Material 3 depends on:** nothing in `material/material`. Material 3 depends on `material-ripple` for the `RippleAlpha` type only (section 5), and its tests use `material-icons-core` (pinned to the 1.7.5 artifact, not in this checkout); compose-rs already has the core filled icons.
- **What porting it would cost:** most of its components are Material 3's under another theme (`Colors` and content alpha instead of color roles and tonal elevation), so a port would reuse compose-rs's layouts, anchored states and nested scrolling, but it's still a second component set: roughly 55 composables and their defaults, `BackdropScaffold`, `BottomDrawer` and `BottomNavigation` new, and 1,097 tests to adapt.

**Recommendation: out of scope for now.** Material 3 is Compose's current design system and has ~1,900 tests' worth of gaps first (section 1); Material 2 adds no capability Material 3 apps need, and compose-rs's users port Material 3 apps. Revisit when Material 3 is at parity, if users ask for Material 2 apps, and then as its own crate (`compose-material`) sharing the anchored-state and nested-scroll pieces.
