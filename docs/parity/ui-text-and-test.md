# Parity ledger: ui-text and the test framework (ui-test)

What compose-rs has of two Jetpack Compose libraries, test file by test file and API by API, and what's missing: `compose/ui/ui-text` (styled text, paragraphs and their queries, fonts, text input types) and `compose/ui/ui-test` with `ui-test-junit4` (Compose's test framework). The second matters most: every porting agent writes its tests against compose-rs's harness (`compose::test`, `crates/compose-test`), so its gaps come first in the suggested order.

## Scope

- **Reference:** androidx-main at `d153d87ed76`, under `frameworks/support/`:
  - `compose/ui/ui-text`: `src/androidDeviceTest` and `src/androidHostTest` (`commonTest` has no tests at this commit);
  - `compose/ui/ui-test`: `src/androidDeviceTest` and `src/androidHostTest` (three `commonMain` files mention `@Test` only in KDoc);
  - `compose/ui/ui-test-junit4`: `src/androidDeviceTest` and `src/androidHostTest`.
  The public API is each module's `api/current.txt`.
- **compose-rs side** (commit `7f744da`): `crates/compose-ui/src/{text.rs, annotated.rs, text_input.rs, text_selection.rs, semantics.rs, input.rs}`, `crates/compose-foundation/src/{text.rs, text_field.rs, text_input.rs}`, `crates/compose-skia/src/text.rs`, `crates/compose-android/src/{text.rs, input_method.rs}` with `android/compose-rs/src/main/java/rs/compose/android/TextMeasurer.kt`, `crates/compose-test`, and the tests of those crates.
- **Counting:** a test file is a Kotlin file in those source sets with at least one `@Test`; its tests are `grep -cE '^\s*@Test(\(|\s|$)'`.
- **What other areas use:** the ui-test API's priority below counts the files using each API among the 2,317 test files of the rest of `frameworks/support/compose` (every module but ui-test itself), by `grep -l`.

**In short.** compose-rs's text has the pieces its widgets need, behind its own `TextMeasurer` trait: `TextStyle` with 10 of Compose's 26 fields, `SpanStyle` with 8 of 18, `AnnotatedString` with span styles only, `LineHeightStyle` without `Mode`, a `TextLayoutResult` snapshot without queries, generic and named font families, the keyboard types. There's no public `Paragraph`, no `ParagraphStyle`, no annotations or links, no fonts from files, no `TextRange`/`TextFieldValue`/edit commands, no locale. Its harness has Compose's core loop (finders on the merged or unmerged tree, `perform_click`, text and key input, a main clock with auto-advance, exact-text and state assertions), but no injection scopes (398 raw `send_pointer` calls and about 30 local `tap`, `drag`, `swipe_up`, `fling` and `bounds` helpers across the suites stand in for them), no bounds or displayed assertions, no collections or tree selectors, no image capture, no `waitUntil`, no state restoration tester.

## What compose-rs has today

**Text** (`compose_ui::text`, `annotated`, `text_input`):

- `TextStyle { color, font_size, font_weight, font_style, font_family, letter_spacing, text_decoration, text_align, line_height, line_height_style }`, `DEFAULT`, `merge`, `has_same_layout_affecting_attributes`; units are `Sp` only (no `Em`).
- `SpanStyle { color, font_size, font_weight, font_style, font_family, letter_spacing, text_decoration, background }`, `over(&TextStyle)`.
- `AnnotatedString { text, span_styles }` with `SpanRange { style, start, end }` over **byte** offsets (D140), `build`, `runs` (Compose's span flattening), `AnnotatedStringBuilder` (`append`, `push_style`, `pop`, `with_style`, `add_style`, `to_annotated_string`).
- `FontWeight(u16)` with `NORMAL`, `MEDIUM`, `BOLD`; `FontStyle { Normal, Italic }`; `FontFamily { SansSerif, Serif, Monospace, Cursive, Named(&'static str) }`; `TextDecoration { underline, line_through }` with `|`; `TextAlign` (6 values; unspecified is `None`); `TextOverflow { Clip, Ellipsis, Visible }`; `LineHeightStyle { alignment: LineHeightAlignment { top_ratio }, trim: LineHeightTrim }` with `DEFAULT`.
- `TextLayoutResult { size, line_count, first_baseline, last_baseline, did_overflow_width, did_overflow_height }` (a snapshot, `has_visual_overflow`).
- The platform trait `TextMeasurer` (`layout`, `layout_annotated`, `metrics`, `did_exceed_max_lines`, `max_intrinsic_width`, `relayout`, `layout_probe`, `restyle`, `hit_test`, `is_right_to_left`, `cursor_rect`, `selection_rects`, `text`, `release`), implemented by `FixedTextMeasurer` (tests: advance 0.5 em, line 1.25 em), `SkiaTextMeasurer` (SkParagraph, system fonts) and `AndroidTextMeasurer` (`StaticLayout`/`BoringLayout` in Kotlin).
- `ImeAction` (8 values), `KeyboardType` (9), `KeyboardCapitalization` (4), `ImeOptions { single_line, capitalization, auto_correct, keyboard_type, ime_action }`; foundation's `KeyboardOptions`, `KeyboardActions`, `VisualTransformation`, `PasswordVisualTransformation`, `OffsetMapping` (byte offsets).

**Harness** (`compose_test`, `crates/compose-test/src/lib.rs`, `matcher.rs`):

- Rules: `compose_test(content)` (400×800 px, density 1, `FixedTextMeasurer`), `compose_test_with(size, density, measurer, content)`, `ComposeTestRule::sized`, `with_manual_clock`, `with_host`, `use_optimizations`; the rule composes at once (no later `set_content`).
- Clock: `wait_for_idle`, `set_auto_advance`, `advance_time_by(Duration)`, `advance_time_by_frame`, `current_time_millis`, `FRAME_DURATION` (16 ms).
- Finders: `on_node`, `on_node_unmerged`, `on_node_with_text`/`_tag`/`_content_description`, `on_all_nodes(matcher, index)`, `count_nodes`.
- Matchers (over a node's `SemanticsConfiguration` only): `has_text`, `has_text_containing`, `has_test_tag`, `has_content_description`, `has_role`, `has_click_action`, `is_enabled`, `is_not_enabled`, `is_focused`, `is_focusable`, `Matcher::new(description, |config| …)`, `and`, `or`, `!`.
- Interaction: `fetch_semantics_node`, `node_id`, `perform_click`, `perform_semantics_action`, `perform_text_input`, `request_focus`, `perform_key_press`, `assert_exists`, `assert_does_not_exist`, `assert_is_enabled`/`_not_enabled`/`_on`/`_off`/`_focused`, `assert_text_equals`.
- Rule-level input: `press_key`, `type_text`; the host underneath (`ui.host()`) has `send_pointer`, `send_key`, `send_text`, `send_preedit`, `perform_ime_action`, `resize`, `set_density`, `set_layout_direction`, `set_configuration`, `set_window_insets`, `save_state`/`restore_state`, `semantics_tree`, `display_list`.
- Extras Compose lacks: `recomposition_counts`, `CountingTextMeasurer`/`TextLayoutCounter`, `draw_snapshot`, dumps (`dump_tree`, `dump_semantics`, `dump_display_list`, `dump_slots`), event scripts (`run_script`, `check_script`).

Text specifics:

- **Offsets.** compose-rs's `AnnotatedString`, `OffsetMapping` and cursor APIs take **byte** offsets (D140); Compose's are UTF-16 indices. Convert expected offsets for any non-ASCII text.
- **Metrics.** `FixedTextMeasurer` advances 0.5 em and makes lines 1.25 em; Compose's test font (`FontTestData.BASIC_MEASURE_FONT`) advances 1 em with 1.2 em lines. Rescale expectations, or wait for test-font. The default font size is 14 sp in both.
- **Measured width.** A text's width is its max intrinsic width rounded up and kept in the constraints, as Compose's `finalMaxWidth` (D104); compare to Compose's `TextLayoutResult.size`, not `multiParagraph.width`.
- **Parity mode.** A test of Compose's own behaviour calls `compose::test::use_optimizations(Optimizations::NONE)` first (D610); the rules default to the recommended set, whose text optimization (`REUSE_PARAGRAPH_AT_SAME_LAYOUT_WIDTH`) is off by default anyway.

### Behaviour that probably differs from Compose

1. **Recomposition isn't tied to frames.** `UiHost::has_pending_work` counts invalid composition scopes, so `wait_for_idle` and the idle wait that ends `advance_time_by` recompose at once, at the current clock time. Compose recomposes only on a frame: with auto-advance, waiting for idle moves the clock 16 ms per frame; with a manual clock, nothing recomposes until a frame is due. So in compose-rs a state written by an effect at t = 100 ms shows at 100 ms, where Compose shows it at 116 ms, and an animation started by a click starts a frame earlier than Compose's. Caught by `ui-test/…/junit4/ApplySnapshotImmediatelyTest.kt` (`test`), and by frame-counting animation tests elsewhere.
2. **`advance_time_by` doesn't round to frames, and its frames restart at each call.** Compose's `advanceTimeBy(ms)` rounds up to a multiple of 16 ms unless `ignoreFrameDuration`, and its frames keep a steady cadence. compose-rs advances exactly, and its first frame is 16 ms after the call starts, so `advance_time_by(15)` repeated never produces a frame. Caught by ApplySnapshotImmediatelyTest (advances of 99, 1, 15, 1 ms) and InfiniteAnimationTest (`testInfiniteAnimation_manualAdvancing_doesRun`). Also `current_time_millis` starts at the wall clock (Compose's at 0): `injectionscope/touch/SynchronizedWithMainClockTest.kt` compares event times with it.
3. **Infinite animations never idle.** With the default clock, a composition holding an infinite transition makes `wait_for_idle` panic after a minute of test time; compose-rs's own infinite-transition tests all use `with_manual_clock`. Compose's test policy lets the UI idle and keeps the animation still. Caught by `InfiniteAnimationTest.kt` (`testInfiniteTransition_finishes`, `testInfiniteAnimation_autoAdvancing_doesNotRun`); it affects every ported test with a progress indicator.
4. **Clicks take no time.** Compose's touch `click` is a down, a move one event period (16 ms) later, then an up (`TouchInjectionScope.click`); compose-rs's `perform_click` presses and releases at the same instant. With notes 1 and 2, double-tap and long-press timings in ported tests need explicit `advance_time_by` calls. Caught by `injectionscope/touch/DoubleClickTest.kt` and `LongClickTest.kt` once touch injection exists.
5. **`perform_click` is a mouse click.** `PointerEvent::press` defaults to `PointerType::Mouse`; Compose's Android `performClick` is a touch tap. Touch-only behaviour (input mode switching to touch, touch slop, text selection handles, hover) differs. Caught by `injectionscope/touch/ClickTest.kt` and `RobolectricComposeTest.kt` (`isTapFired_…`) once ported with touch injection.
6. **`assert_text_equals` is ordered.** Compose's `assertTextEquals`/`hasTextExactly` compares the node's texts and the expected values as sets (each contains the other). A merged node whose texts come in another order passes in Compose and fails here. Caught by `assertions/AssertText.kt` (`textAndEditText`).
7. **Word boundaries come from UAX #29.** compose-rs's double-click and word moves use `unicode-segmentation`, with no dictionary for Chinese, Japanese, Thai, Khmer or Lao (UAX #29 breaks between most of their characters); Compose's `WordIterator` uses ICU's `BreakIterator` with dictionaries. Caught by `android/selection/WordIteratorMultiLanguageTest.kt` (`japanese_kanjiAndHiragana_…`, `chineseSimplified_…`, Thai) and `WordBoundaryTest.kt` (`testGetWordStart_CJK`).
8. **Desktop line heights align centered or proportionally only.** `skia_text_style` sets half-leading for `LineHeightAlignment::CENTER` and leaves every other ratio (top 0, bottom 1, custom) to SkParagraph's proportional placement; Android ports Compose's span exactly. Caught by `ParagraphIntegrationLineHeightStyleTest.kt` (`singleLine_top_trim_*`, `singleLine_bottom_trim_*`, `multiLine_top_*`) run on the Skia measurer.
9. **The password mask counts characters, not UTF-16 units.** compose-rs repeats the mask once per `char`; Compose's `PasswordVisualTransformation` once per UTF-16 unit (`text.length`), so an emoji outside the BMP shows two bullets in Compose and one here. Caught by `input/PasswordVisualTransformationTest.kt` extended with a surrogate pair (and Compose's own `BasicTextField` password tests).
10. **RTL detection on the desktop knows two blocks.** compose-skia's `first_strong_is_rtl` treats U+0590–U+08FF and the Arabic and Hebrew presentation forms as RTL, and any other alphabetic character as LTR, so text starting with an RTL script outside those ranges (Adlam, Hanifi Rohingya, Imperial Aramaic, in the SMP) lays out left to right. Caught by a direction test with such a script, in the style of `ParagraphIntegrationTextDirectionTest.kt`; Compose resolves the direction with the platform's bidi algorithm.
11. **`FontWeight` takes any `u16`.** Compose rejects weights outside 1..1000. Caught by `font/FontWeightTest.kt` (`constructor does not accept greater than 1000`, `… less than 1`).
12. **Empty spans are dropped.** `AnnotatedStringBuilder::to_annotated_string` keeps only ranges with `start < end`; Compose keeps zero-length ranges (and collapses others into them on `subSequence`). Caught by `AnnotatedStringTest.kt` (`creating_item_with_start_equal_to_end_does_not_throw_exception`, `subSequence_collapsed_item_with_itemStart_equalTo_rangeStart`).
13. **Semantics bounds are unclipped.** `SemanticsNode::bounds` ignores clips: a child scrolled out of a scroll container's viewport, but still placed and inside the root, keeps bounds that look visible, so an `assertIsNotDisplayed` hand-written as a bounds-in-root check passes where Compose's fails, and the reverse for `assertIsDisplayed`. Caught by `IsDisplayedTest.kt` (`componentInScrollable_isNotDisplayed`, `rowTooSmall`) once harness-assertions lands.
