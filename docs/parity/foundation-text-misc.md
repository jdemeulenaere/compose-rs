# Parity ledger: foundation text, selection and miscellaneous APIs

What Compose's `compose/foundation/foundation` tests and public API in this area cover, and where compose-rs stands against each. It drives the porting work: each row says whether its tests can be adapted now (`port`), are already exercised (`covered`), wait for a missing feature (`feature:<name>`, defined in [Missing features](#4-missing-features)), or don't apply (`n/a`).

## 1. Scope and totals

- **Reference:** androidx-main at `d153d87ed76` (2026-10-25), `frameworks/support/compose/foundation/foundation`: the test source sets `src/androidDeviceTest` and `src/androidHostTest` (the module has no `commonTest`), and the API in `api/current.txt` (`api/restricted_current.txt` is the same file with a different surface tag).
- **In this area:** every test file outside the gestures, scrolling and lazy areas: the `text/**`, `textfield/**`, `selection/**`, `shape/**`, `style/**`, `content/**`, `contextmenu/**`, `draganddrop/**` and `relocation/**` directories, the host-side `text/**`, `shape/**`, `style/**`, `contextmenu/**` and `MutatorMutexTest`, and the root-package device tests for clickable, focusable, hoverable, indication, interactions, border, background, image, canvas, marquee, magnifier, tooltip, external surfaces, progress semantics, system gesture exclusion and keep-clear rects. Left to the gestures/scrolling/lazy ledgers: the root `gestures/**` (`text/selection/gestures/**` is here), `lazy/**`, `pager/**`, `anchoredDraggable/**`, `focus/LazyListFocusableInteractionTest`, and the root `Scroll*`, `Scrollable*`, `*Draggable*`, `*Overscroll*`, `Transformable*`, `*Scrollable2D*`, `LazyListFocusableInteractionTest` files. Shared with them: `MutatorMutexTest` and `relocation/BringIntoViewScrollableInteractionTest` (listed here).
- **compose-rs side:** `crates/compose-foundation` (`text.rs`, `text_field.rs`, `text_input.rs`, `image.rs`, `shape.rs`, `tooltip.rs`), `crates/compose-ui` (`modifier.rs`, `nodes.rs` for clickable/toggleable/combined clickable/hoverable/focusable/border/background, `interaction.rs`, `text_selection.rs`, `graphics.rs` for shapes), `crates/compose-android/src/input_method.rs`, and their tests.

**Totals:** 330 test files with 4,937 `@Test` methods (counted with `grep -cE '^\s*@(Test|ParameterizedTest)\b'`, so abstract bases such as `NodeInvalidationTestParent` count their own methods once). Another 48 files in these directories are helpers without tests and aren't listed.

Of the `n/a` tests, 578 (53 files) test the **deprecated** value-based `BasicTextField` and its internals (see below) or `ClickableText`/`onFocusedBoundsChanged`, 389 (23 files) test Compose-internal data structures or helpers whose behaviour other files check through public API, and 28 (4 files) test Compose's own test infrastructure or compare a golden image; 40 (1 file, `TextFieldTextToolbarTest`) run only with the old context menu, which compose-rs doesn't port (D2031). The remaining n/a rows each say why. Three rows (`textfield/TextFieldContextMenuTest` and `textfield/TextFieldTextContextMenuBuilderTest`, `ported`, and `textfield/TextFieldToolbarTest`, `feature:`) mix the legacy and state-based fields: their 41 legacy (`btf1`) tests are n/a too.

The `partial` rows add more demand on `clickable-parity`, `focusable-parity` and `image-painter`, and on ui's input mode and indirect pointers (`ClickableTest`, `CombinedClickableTest`, `ToggleableTest`, `SelectableTest` and `FocusableTest`'s remaining scenarios).

**The value-based `BasicTextField` is deprecated.** At this commit both `BasicTextField(value: String, onValueChange, …)` and `BasicTextField(value: TextFieldValue, …)` are `@Deprecated("Use the BasicTextField(state: TextFieldState, ...) overload instead …")` (`BasicTextField.kt` lines 799 and 970). compose-rs's only text field is the `String` one (D96). So its tests (`textfield/**`, `text/CoreTextField*`, the `Legacy*` IME tests and the legacy internals) are `n/a` here, and the state-based field's tests (`text/input/**`) wait on `text-field-state`, even where compose-rs's field already does what they check (the rows say so). `KeyboardActions`, `KeyboardOptions` and `VisualTransformation` aren't deprecated themselves, but in foundation only the deprecated field takes `KeyboardActions` and `VisualTransformation`.

- **Status:** done (D1685): `LOCAL_AUTOFILL_HIGHLIGHT_BRUSH`, drawn over a filled field's inner field until its text changes.

### shift-click-selection
- **What:** Shift held while clicking in a field extends the selection from its anchor to the click, in LTR and RTL text and empty regions; nothing in a read-only field's cursor.
- **Tests:** `TextFieldShiftClickTest` (9).
- **Depends on:** ui's pointer events carrying the keyboard modifiers: **in** (`PointerKeyboardModifiers`, `input.rs`); the state-based field reading them is what's left.
- **Size:** S. **Experimental:** no.

### selection-on-back
- **What:** Android's Back key (key up) clears a field's selection and the event isn't propagated; with only a cursor handle shown it isn't consumed (Compose's `cancelsTextSelection`).
- **Tests:** `TextFieldSelectionOnBackTest` (4).
- **Size:** S. **Experimental:** no.

### What the harness lacks, by priority

> Since the harness's milestone 1 (D900–D905), compose-test has Compose's clock model (rounding, frames on the test clock, `advance_time_until`, `wait_until`, the infinite-animation policy), bounds and displayed assertions, matchers over the tree and selectors (`on_children`, `on_parent`, collections), the touch, mouse (primary button) and key injection scopes, `perform_scroll_to`, `capture_to_image` with `assert_pixels`, and `print_to_string`; `perform_click` is a touch click. The notes in this section and the mapping above that call these missing are out of date: docs/09 lists the API, and [ui-text-and-test](ui-text-and-test.md) what is still missing. Existing tests that relied on the old timing gained a frame where they wait for a recomposition (D900).

1. Pointer buttons and keyboard modifiers on `PointerEvent` (right click for every context-menu test, Shift+click for `TextFieldShiftClickTest`): a ui-area change, then `perform_mouse_input`-style helpers.
2. A touch/mouse gesture DSL (`down`, `move_to`, `up`, `long_click`, `double_click`, `swipe`) on `SemanticsNodeInteraction`, defaulting to touch as Compose's.
3. Semantics assertions and text actions listed above (`assert_is_selected`, `assert_editable_text_equals`, `assert_text_selection_range`, `perform_text_replacement`, `perform_text_clearance`, `perform_text_input_selection`).
4. An interaction recorder: the foundation suite has its own (`interaction_helpers::record`, `kinds`, `ends`); compose-test could take it.
5. A pixel capture (`capture_to_image()` through Skia's raster backend, available when the test crate depends on compose-skia), for the border/background/selection-color tests.
6. Fakes for the text toolbar and the input connection, and a touch/keyboard input mode switch.

### Behaviour that probably differs from Compose

- **Focusable by input mode.** As Compose's, a clickable is `Focusability::SYSTEM_DEFINED` (D1272): no focus in touch mode; `focusable` always. `ClickableTest.requestFocus_touchMode`, `FocusableTest.requestFocus_touchMode`.
- **Triple click in `SelectionContainer` selects the whole text**, Compose's selects the paragraph (`SelectionAdjustment.Paragraph`, `SelectionGestures.kt`). The field already selects the paragraph. `SelectionAdjustmentTest` (paragraph cases).
- **Selection order is placement order** (D151); Compose sorts selectables by position in the container (top to bottom, then start to end). They differ where placement order isn't visual order (a `Box`'s stacking, `z_index`, reversed layouts). `SelectionRegistrarImplTest.sort_vertical_oriented`, `SelectionContainerTest.selectionRegistrar_sortsLazySelectablesCorrectly`.
- **Touch selection, in part** (D2008 to D2013). A container's handle drags go by characters where Compose's accelerate by words across texts; a finger's double tap in a container selects nothing; no auto-scroll while dragging, no toolbar, no magnifier. `SelectionContainerTest`'s auto-scroll tests, `TextFieldTextToolbarTest`.
- **The cursor doesn't blink.** `TextFieldCursorTest.cursorBlinkingAnimation`.
- **No default field width.** compose-rs's value-based field is as wide as its text plus the cursor; Compose's is at least 10 "H" characters wide (`DefaultWidthCharCount`), as compose-rs's state-based field is (D1137). `BasicTextFieldTest.textField_textAlignCenter_defaultWidth`. Material's 280 dp minimum hides it there.
- **Single-line new lines.** compose-rs's value-based single-line field drops typed or pasted `\n` (not `\r`), and draws a `value` containing either as is, as before; the state-based single-line field is Compose's: it keeps the text and shows `\n` as a space, `\r` as U+FEFF (D1134). `SingleLineOutputTransformationTest`.
- **Initial cursor.** The value-based field starts at the start (as `TextFieldValue`'s default); `TextFieldState::new(text)` puts the cursor at the end, as Compose's (`TextFieldStateTest.customInitialTextAndDefaultSelection`, ported). Ported field tests must not assume the old start.
- **The state-based field (D1131, D1132):** a single line draws a new line as it is; no default width; cut, paste and undo restart the input method by the state's rule (only under a composition), not D1664's.
- **Undo grouping** (D118), the value-based field's (the state-based field has Compose's, D1132): compose-rs joins typing within 5 s of the last typed text and clears the history when the application changes the value; Compose merges by edit type and direction within 5 s of a group's first edit (deletions too, new lines never) and records programmatic edits. `TextUndoTest`, `BasicTextFieldUndoTest.programmaticEdits_contributeToUndoHistory`, `undoMerges_deletes`.
- **Back doesn't collapse a field's selection.** `TextFieldSelectionOnBackTest.whenBackPressed_andReleased_textFieldClearsSelection`.
- **Keys the field ignores:** numpad navigation keys, Shift+Insert/Ctrl+Insert, `DirectionCenter`. `textField_shiftInsert`. (Page Up and Page Down move the cursor by the field's height, D1460: `text_input.rs`, porting `TextFieldKeyEventTest.textField_pageNavigationDown` and its three others; `CommonTextFieldKeyEventTest.textField_pageUp` isn't ported.)
- **API shape** (fixed, D1022): `Image`'s `content_description` was `Option<&'static str>`; it takes `Option<impl Into<SharedString>>` now, a description built at run time too.
