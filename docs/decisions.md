# Design decisions

Each decision with the alternatives considered. **Revert cost**: *low* (local edit), *medium* (one subsystem), *high* (touches most of the code).

| # | Decision | Alternatives considered | Revert cost |
|---|---|---|---|
| D1 | The Compose compiler plugin's job is done by a proc macro, `#[composable]`, working on syntax; type-dependent decisions go through traits that rustc resolves | a compiler fork or rustc driver plugin (unstable, heavy); a runtime-only design without a transform (no skipping, keys from `#[track_caller]` line numbers) | high |
| D2 | The current composer is a thread-local; composables are plain functions with no hidden parameter | an explicit `&mut Composer` parameter injected by the macro (faster by a TLS lookup, but every composable call would have to pass it, so callers must also be transformed) | medium |
| D3 | Group keys are `const` hashes of the declaration path plus structural indices, never line numbers | `#[track_caller]` locations (no macro needed for keys, but keys depend on line numbers, so test dumps and keyed state change with unrelated edits and formatting) | medium |
| D4 | No `$changed` bits from callers; each callee compares its arguments with its kept tuple | Compose's caller-provided static/same/different bits (saves comparisons for forwarded arguments, but needs caller-side transformation) | low |
| D5 | Strong skipping through a `ComposeArg` trait, **identity first, then contents only where cheap** (user): identity for `Rc`/`Arc`/handles/callbacks, value equality for small values, no implementation for `Vec`/`HashMap` (wrap in `Rc`) | deep `PartialEq` for everything (expensive compares, which strong skipping avoids); stability inference (Compose's pre-strong-skipping model) | medium |
| D6 | `String` is `ComposeArg` by value comparison | require `SharedString` everywhere (stricter, noisier) | low |
| D7 | Composables with borrowed parameters are non-restartable and never skip; data to skip on is passed as `Rc<T>` or state handles | identity derived from where the borrow comes from (impossible: a proc macro can't see where a borrow comes from, and kept arguments can't hold borrows) | medium |
| D8 | Kept arguments in one typed slot; restart is a non-capturing `fn(&dyn Any)` pointer: no allocation per pass | a boxed restart closure capturing clones of the arguments (allocates whenever the composable runs) | low |
| D9 | `move` and capture-free closures are memoized on their syntactically found captures (borrowing closures run at once and are left alone; call macros make content closures `move`); captures that aren't `ComposeArg` make the lambda always changed (autoref specialisation), and closures containing unknown macros are always changed | no memoization (lambdas always change, so composables taking handlers never skip: the todo-rows problem); requiring `Callback::new` keyed by hand | medium |
| D10 | Content lambdas have no restart scope of their own; state read inside them registers the invoking composable's scope | a scope per composable lambda, as in Compose (finer, but needs a group and restart function per lambda) | low |
| D11 | Named, default, trailing and format arguments through a generated `macro_rules!` call macro per composable (`Button!(…)`), tried first (user); the plain function stays callable | builder per composable; argument structs with `..Default::default()`; one `view!` DSL for bodies | medium |
| D12 | Composables keep Compose's PascalCase names (the macro allows `non_snake_case`); everything else follows Rust naming | snake_case composables (idiomatic Rust, but further from Compose) | low |
| D13 | `Modifier` is both a type and a `const` of that type, so `Modifier.padding(…)` reads as in Kotlin | `Modifier::new().padding(…)` | low |
| D14 | State: `Copy` generational handles (`MutableState<T>`, `State<T>`) into a per-thread arena, with an owning `OwnedState<T>` for state in remember slots and data; handles are `!Send` | an owning `MutableState` with implicit weak captures (impossible without compiler support); `Rc<RefCell<T>>` state (clones before every `move` closure, possible cycles) | high |
| D15 | Writes during composition are a misuse (debug panic): composition is a pure function of state | Compose's permissive backward writes | low |
| D16 | Observation only, no snapshot isolation yet; the cell layout leaves room for record chains | full MVCC snapshots now | medium |
| D17 | Rules R1–R3 ([05](05-state.md)): release order, deferred free to the end of the next pass, `try_*` APIs and panics naming the creation site for handles kept outside the UI tree | reference-counting handles (no stale handles, but hidden ARC-like costs and cycles) | medium |
| D18 | `Modifier` is an inline `SmallVec` of a built-in element enum plus `Custom(Rc<dyn ModifierNodeElement>)`; elements diff in place into `ModifierNode`s; no `composed` | all elements as trait objects (allocates per element); a fixed-size `Copy` chain with a separate handler table | medium |
| D19 | Scoped modifiers take the scope token: `Modifier.weight(row, 1.0)` | unchecked `Modifier.weight(1.0)` with a runtime error outside `Row`/`Column` | low |
| D20 | `Box`, `Column`, `Row` are ordinary composables over a public `Layout`/`MeasurePolicy`, as in Compose | built-in node kinds for `Column` and `Row` | medium |
| D21 | Text behind a `TextMeasurer`, implemented with each platform's Compose text stack: SkParagraph on desktop, `StaticLayout` on Android (user); bundled fonts in tests | Parley everywhere (pure Rust, but text would differ from Compose); SkParagraph on Android too (one code path, but differs from Android Compose) | medium |
| D22 | One thread for window, events, composition, layout and drawing | a program thread separate from the main thread (needs a frame mailbox and input channel) | medium |
| D23 | Drawing through Skia (`skia-safe`, prebuilt) on desktop, like Compose Desktop's Skiko (user) | a custom CPU rasterizer then Vello (pure Rust, smaller, but pixels differ from Compose) | medium |
| D24 | No hot reload (user): an edit is an incremental build and a restart, kept to about 1–3 s by the framework's build rules, a `dynamic` feature for development and a guide for apps ([08](08-fast-builds.md)) | hot patching through Subsecond (experimental, can't change the layout of live data, adds epochs, forced passes and type fingerprints to the runtime); dylib reloading (coarse, needs a fixed ABI between host and library) | low |
| D25 | On Android, `ComposeRsView` is a plain `View` drawing in `onDraw`, embeddable in Kotlin Compose with `AndroidView` (user) | a `SurfaceView` with its own renderer (a separate layer that Compose's transforms, clipping and scrolling don't reach); a native activity only | medium |
| D26 | Android draws through the system `Canvas` via a batched display-list replayer: one JNI crossing per frame, no Skia shipped, the system's Skia underneath (user) | native Skia into an `AHardwareBuffer` shown as a `Bitmap` (no per-op Java, but ships ~10 MB of Skia per ABI and differs slightly from the system's pixels); kept as a later option behind the `Renderer` interface | medium |
| D27 | On Android, the composition runs on the main thread, driven by Choreographer frames only while scopes are invalid | a separate composition thread (needs synchronization with the view's drawing) | low |
| D28 | (agent) Slots hold an `Rc<dyn Any>`; there is no `Slot::Word` for small `Copy` values | inline words for small values (detecting `Copy` needs specialization; a size-and-`needs_drop` test plus a bitwise copy works but adds `unsafe` for one allocation saved when a value is first remembered, never in steady state) | low |
| D29 | (agent) `update_kept(changed: FnOnce(&K) -> bool, make: FnOnce() -> K)`: the kept tuple is built only when the arguments differ, and updated in place when nothing else holds it, so a steady-state call clones and allocates nothing | the outline's `update_kept(new: K, changed)` (clones every argument on every pass, and allocates for `String` arguments) | low |
| D30 | (agent) `ComposeArg` doesn't require `Clone`; kept arguments need `Clone` on their own, for restarts | `ComposeArg: Clone` as in the outline (then a struct holding an `OwnedState`, which isn't `Clone`, couldn't derive `ComposeArg` field by field, as the todo sketch's `Todo` does; such a struct is passed as `Rc<Todo>`) | low |
| D31 | (agent) The `Applier` has an associated `Node` type, returns a `NodeRef` per inserted node, and has `release(node)`; node insertions and moves are applied during the pass (adjacent moves coalesced), removed nodes are detached during the pass and released at its end; during the pass the applier is part of composition and must not write state | `Applier<N>` with a type parameter (ambiguous inference); Compose's recorded change list applied after the pass (needed for concurrent composition, which this design doesn't have) | medium |
| D32 | (agent) Recomposition walks from the root through dirty flags that invalidation sets on a scope's ancestors; tree order, "never twice" and "never inside a removed group" follow from the walk | a list of invalid scopes sorted by tree position (needs positions or anchors in a linked tree) | medium |
| D33 | (agent) A state read records the scope's epoch, bumped when its body is known to run (`skipping()` says no or `update_kept` reports a change, not when the group starts: a scope that may still skip must keep its reads current, a bug the review found); a write invalidates only scopes whose latest run read the cell, and prunes the rest | invalidate every scope that ever read the cell (over-recomposes after a read stops); clear a scope's reads at each run (needs a per-scope read list) | low |
| D34 | (agent) A retired cell is freed at the end of the next pass of any composition on the thread; with no composition on the thread it is freed at once; dropping a composition frees the cells it retired, the last one frees all | per-composition retirement lists (cells aren't owned by a composition) | low |
| D35 | (agent) A panic unwinding out of a pass poisons the composition: further passes panic, and dropping it releases everything exactly once (`on_abandoned` for observers never remembered) | continuing after a panic (the slot table is mid-pass and can't be trusted); `catch_unwind` inside the runtime (needs `UnwindSafe` bounds everywhere) | low |
| D36 | (agent) Remember observers are remembered with `remember_observer`, returning an `Observed<T>` handle | detecting `RememberObserver` in `remember` (needs specialization) | low |
| D37 | (agent) Group matching scans siblings linearly from the cursor; reversing 1,000 keyed items costs about 1.4 ms | Compose's hash map of pending keys (an allocation and hashing on every mismatch); can be added for long sibling lists if profiles ask | low |
| D38 | (agent) Groups match on kind as well as key and data key | key and data key only, as Compose (a restart and a replace group with the same key would match each other, recreating state either way) | low |
| D39 | (agent) `remember`, `key`, state, `SideEffect` and `DisposableEffect` are built in phase A, with the runtime: its scenarios need them | building them in phases B and C as the roadmap lists | low |
| D40 | (agent) Writes during composition panic in debug builds only; release builds let them through, invalidating as usual | panicking in release too (a check on every write) | low |
| D41 | (agent) Generated groups are drop guards (`RestartGroup`, `ReplaceGroup`, `region`), so early exits keep groups balanced; they don't end their groups while a panic unwinds | rewriting `return`, `break`, `continue` and `?` to end groups first (a scope-aware rewrite of every jump; `?` needs its error path expanded) | low |
| D42 | (agent) A region group does nothing outside a composition pass | strict region groups (a PascalCase tuple-struct or variant call in a handler closure would then panic when the handler runs) | low |
| D43 | (agent) Generated code calls `::compose::__private`; crates without the facade alias their runtime (`extern crate compose_runtime as compose;`, which the runtime does for itself) | a `#[composable(crate = …)]` option on every composable; finding the dependency's name by reading `Cargo.toml` in the macro (slower expansions) | low |
| D44 | (agent) `&'static T` parameters keep a composable restartable; other references make it non-restartable | treating every `&` as a borrow (then `&'static str`, a `ComposeArg` in docs/03's table, couldn't be passed to a restartable composable) | low |
| D45 | (agent) Composables are free functions: a `self` receiver is rejected | supporting methods (the restart function must name the method through `Self`, and a receiver is a borrow) | low |
| D46 | (agent) The `#[composable]` expansion goldens are unit tests in `compose-macros`, pretty-printed with `prettyplease`; compile-fail tests use `trybuild` in the facade | `macrotest` (needs `cargo-expand` installed and its output depends on rustc's pretty-printer) | low |
| D47 | (agent) A composable's group key hashes the crate name, the source file relative to the package (or to `OUT_DIR`, or just the file's name for code from another crate's macro), and the function's name, and the macro emits it as a literal; region keys are literals too. Composables whose keys collide (generic instantiations, same-named composables in one file's inline modules) don't match each other's groups: a restart group records its composable's identity, the `TypeId` of its restart closure, so restartable generic composables get a `'static` bound on their type parameters; a non-restartable composable's replace group records the type name of a marker closure (no `TypeId`: its parameters may borrow) | D3's `const` hash of `module_path!()` (a `const` item per composable costs about 0.3 ms of compile time to check and evaluate; this measured 2.75 s → 2.3 s for a clean build of 1,000 composables); comparing restart-function addresses (an `#[inline]` composable called from another crate has a copy per crate in debug builds, so its state was lost on every pass, which a review found) | low |
| D48 | (agent) A `Composer` is a handle to its thread's runtime, valid in any pass on the thread | a composer bound to one pass (a content lambda capturing it would panic when its invoker restarts in a later pass) | low |
| D49 | (agent) A pass ends before its deferred work (releases, observers, drops, side effects) runs, so that work may compose other compositions; frame requests made during a pass, its deferred work or a disposal are delivered when it ends, so a frame requester may recompose synchronously, and a composition's next pass waits until its previous pass's effects have all run | running the deferred work inside the pass (then a popup composed from an effect, or an immediate scheduler, panics) | low |
| D50 | (agent) `SideEffect` keeps its closure in a remembered slot until the end of the pass, so a pass that runs it allocates nothing; `Composer::record_side_effect` still boxes | boxing every effect, as Compose allocates a lambda (then any scope with a `SideEffect` allocates on every recomposition) | low |
| D51 | (agent) A panic caught (`catch_unwind`) inside the composition leaves the groups it unwound through open; the runtime diagnoses it by name when the groups turn out unbalanced, and poisons the pass | ending groups while a panic unwinds (touching the runtime then could panic again, which aborts); Compose forbids try/catch around composable calls at compile time | low |
| D52 | (agent) In a loop, a call to any macro other than the standard ones (including PascalCase ones) counts as a possible `continue`, giving per-statement groups; and a closure making likely composable calls is a region of its own | trusting macros (an unlabelled `continue` inside a `macro_rules!` expansion isn't hygienic and reaches the loop); no regions in closures (a conditional call in a closure then lends its state to the next call of the same composable) | low |
| D53 | (agent) Rule R2's "code later in the same handler still sees a live cell" holds for hosts that run frames after handlers (the desktop and Android hosts schedule frames); a frame requester that recomposes synchronously runs the next pass inside the handler, and frees the cell there | deferring the free by more passes (no finite deferral survives a synchronous host: the handler's next write runs the next pass too) | low |
| D54 | (agent) `#[derive(ComposeArg)]` bounds the fields that mention a type parameter (`Option<T>: ComposeArg`), not the parameters, so `Shared<Vec<u32>>` with an `Rc<T>` field works | `T: ComposeArg` on every parameter, as std's derives do | low |
| D55 | (agent) The runtime's thread-local has no destructor, so it stays usable from every other thread-local's destructor; at thread exit, a guard thread-local empties the compositions still alive (releasing their nodes and values while everything works) and closes them: a handle still owned elsewhere stays usable as an empty composition until its owner drops it. Once nothing is left at thread exit, the runtime replaces itself by an empty one (continuing the generations), so a thread that dropped everything leaks nothing; what other thread-locals still own stays allocated | disposing them outright (an owner's `Drop` using its handle then panicked inside a thread-local destructor, which aborts); a runtime with a destructor (thread-locals are destroyed in an unspecified order: a handle outliving it aborted, as reviews found) | low |
| D56 | (agent) Each composable's call macro is a one-arm `macro_rules!` forwarding to a shared function-like proc macro, `call!`, with a spec of the parameters; `pub` composables' call macros are `#[macro_export]`ed under a hidden unique name and re-exported next to the function, the others re-exported with the function's visibility | a `macro_rules!` muncher per composable (it must call itself, and a macro-expanded `#[macro_export]` macro can't be referred to by absolute path within its crate) | low |
| D57 | (agent) Call-macro default expressions are resolved at the call site, as macro arguments are, except `crate::` paths, which become `$crate::` (D66) | resolving them in the callee's module (a declarative macro can't name it; a hidden item per default would need to be imported, and a type-namespace item named like the composable would shadow `Box` and other types) | medium |
| D58 | (agent) Lambdas are memoized where the macro knows they become callbacks: closures and trailing blocks of call macros (marked with their captures; `call!` memoizes those bound to callback parameters), and closures wrapped in `callback(…)`/`Callback::new(…)` | memoizing every closure argument of a likely composable call (a syntactic guess rewrote closures passed to generic `F: Fn` parameters and PascalCase tuple structs into `Callback`s, breaking their types) | low |
| D59 | (agent) `impl Fn(A, …) -> R + 'static` parameters become `Callback<dyn Fn(A, …) -> R>`; callback arguments are passed by value (no `impl Fn(&T)`) | supporting reference arguments (the higher-ranked `dyn Fn(&T)` conversion conflicts with the by-value one: a future-incompatibility coherence warning) | low |
| D60 | (agent) `mutable_state_list_of()`, as Compose's `mutableStateListOf()`: a `Vec` state whose edits always invalidate, so its elements need no `PartialEq`; the todo sketch uses it | requiring `PartialEq` of list elements (`OwnedState` has none) | low |
| D61 | (agent) compose-runtime depends on compose-macros and re-exports `composable`, `ComposeArg` and `call`, so every crate that names its runtime `compose` gets the macros | each toolkit crate re-exporting the macros itself | low |
| D62 | (agent) A memoized lambda's probe is a likely composable call for region groups: a branch, loop or closure containing one gets its group, as Compose's `remember`-based lambdas do | a group per lambda (a group costs more than a slot, on every pass); no groups (the phase C review found callbacks in `if` branches sharing a slot, and optional or looped callbacks shifting later state) | low |
| D63 | (agent) A capture that isn't `ComposeArg` but is zero-sized (a function item, a capture-less closure) is `same`; a callback given as a value (a name or a default) is memoized on itself | always changed (a defaulted `on_click = noop` then made every callee re-run and allocate each pass) | low |
| D64 | (agent) Call-macro markers are a first statement `::compose::__private::marked!(captures);` in the closure body or block, expanding to nothing | an `@memoize` token prefix, then a wrapping `marked!(…)` macro (a user's PascalCase macro matching `$body:block` or a closure pattern couldn't take either) | low |
| D65 | (agent) A call macro invoked by path inside a composable gets the path first (`ui::Label!(@path (ui::Label) …)`, D99), and its expansion calls the function by it; outside composable bodies (a `set_content` closure, a user `macro_rules!`), it still calls the bare name where it is used, so import the composable or call the function | expanding to the bare name everywhere (it called whatever `Name` was in scope at the call site, silently); a fix outside composables would need the macro to name its function's module, which a declarative macro can't | low |
| D66 | (agent) `crate::` paths in `#[default(…)]` become `$crate::`, so a library's defaults resolve in the library (the items must be public, as for any macro) | call-site resolution only (a library default naming its own helper failed in every other crate) | low |
| D67 | (agent) A measure policy places its children in the call that measures them (`scope.measure`, `scope.place`, `scope.layout`), as do layout modifiers | Compose's placement block run after measurement (a boxed closure per measured node, or a second trait method and a stored result per node) | low |
| D68 | (agent) Draw modifier nodes have `draw` (before the content) and `draw_after` (after it, in reverse chain order): Compose's `drawContent()` split in two | a continuation-passing `ContentDrawScope::draw_content()` (borrows the rest of the chain and the tree inside a node's own call) | low |
| D69 | (agent) The built-in modifiers are inherent methods of `Modifier` in `compose-ui`, with their nodes; the scope tokens live there too, with hidden constructors; `compose::foundation` re-exports | extension traits in foundation (every use site would import them), or `Custom` elements (an `Rc` per element per pass) | low |
| D70 | (agent) The macro memoizes closure arguments in modifier chains rooted at the path `Modifier`, as call-macro arguments | memoizing only `callback(…)` (`Modifier.clickable(move || …)` then made every receiver re-run and allocate each pass) | low |
| D71 | (agent) State read while measuring (any policy, custom layout nodes) or drawing (custom draw nodes) is observed per node by a `ReadObserver` in the runtime, as Compose's `SnapshotStateObserver`: a write measures or draws that node again at the next frame, without recomposing. Built-in nodes aren't observed (they read no state) | no observation (layout followed composition only; custom layouts and scrolling couldn't read state) | medium |
| D72 | (agent) The display list is recorded whole whenever anything changed, into a buffer reused across frames; measurement is incremental | per-node display lists (a layer per node, more memory and bookkeeping before profiling asks for it) | low |
| D73 | (agent) `UiTree` is the applier, and owns the text measurer, focus, pointer captures and the display list | a separate `UiApplier` wrapping the tree (one more indirection for every node update) | low |
| D74 | (agent) Application callbacks triggered by input are queued and run after dispatch, with the tree free; `on_key_event` handlers run during dispatch (their result routes the event) and can't reach the tree | running every handler during dispatch (a handler touching the host or the tree would hit a busy applier) | low |
| D75 | (agent) One pointer change per event; a press captures its hit path; Compose's three passes; no hover enter and exit yet | multi-pointer events grouping changes (later, with touch on Android) | low |
| D76 | (agent) Focus moves through focus targets in tree order with Tab, wrapping around; enabled clickables are focus targets, clicked by Enter or Space on key up | Compose's two-dimensional focus search (later, with arrow keys) | low |
| D77 | (agent) The root measures its children with the window's constraints loosened | fixed constraints (every top-level node would fill the window) | low |
| D78 | (agent) `compose-test` measures text with the fixed-advance measurer until `compose-skia` exists (phase F); text finders match exactly by default, as Compose's `onNodeWithText`, with `has_text_containing` for substrings (the counter sketch is updated) | substring matching by default, as the first sketch implied | low |
| D79 | (agent) `TextMeasurer: Any`, so a renderer downcasts the measurer to its own type to draw paragraphs by handle | paragraph objects in the display list (they would be shared between measurer and renderer, and cross into Kotlin on Android) | low |
| D80 | (agent) Memoized lambdas resolve through `resolve_N`/`callback_N` functions per arity (up to four) that spell out the `Fn` bound, so untyped closure parameters are inferred from the callback parameter | a generic `IntoCallback` bound (closure parameters then needed type annotations) | low |
| D81 | (agent) `CompositionLocal` in the runtime, as Compose's `compositionLocalOf`: a provider is a replace group holding the value in a state cell; `current()` walks up the slot table to the nearest provider (through provider groups only since D310), so restarting scopes find it, and reads the cell, so a new value recomposes exactly the readers. Declared as `static`s (their address is their identity) | no locals until later, as first planned (Material's `LocalContentColor` and `LocalTextStyle` need them); a map of provided values copied into every group (memory per group) | low |
| D82 | (agent) `Option<impl Fn(…) + 'static>` parameters are optional callbacks (`Option<Callback<dyn Fn(…)>>`), as Compose's nullable lambdas: a lambda or block given for one is `Some` memoized callback, anything else (`None`) passes as written | `Option<Callback<…>>` written by hand at call sites (`label = Some(callback(…))`) | low |
| D83 | (agent) A memoized lambda nested in another closure (a content block inside a content block) is built on a miss from clones of its captures, so the outer closure stays `Fn`; top-level lambdas move their captures (superseded by D115). A non-`Clone` capture of a nested lambda is a compile error | moving captures out of the outer closure (any non-`Copy` capture of nested content failed to compile) | low |
| D84 | (agent) Capture analysis visits a call macro's arguments as expressions: a named argument's name isn't a use, and names bound in its lambdas are scoped | token scanning only (a named argument `modifier = …` counted as a capture of the local `modifier`) | low |
| D85 | (agent) `on_focus_changed(impl Fn(bool))` passes `hasFocus` (its target, or a node below, has focus), reported on attach and on change | Compose's full `FocusState` (`isFocused`, `hasFocus`, `isCaptured`) as a struct (later, if needed) | low |
| D86 | (agent) `Modifier.semantics(merge, |config| …)` runs its closure at once and keeps the configuration as a value compared by equality; the macro memoizes closures only for the callback-taking modifiers (`clickable`, `clickable_with`, `toggleable`, `on_focus_changed`, `on_key_event`) | a stored closure compared by pointer (never `same`, so receivers never skipped); memoizing every closure in a modifier chain (broke `semantics` and user methods taking closures they run at once) | low |
| D87 | (agent) Closures given to modifiers taking arguments (`Modifier.on_key_event(move \|event: KeyEvent\| …)`) annotate their parameters, as in plain Rust: an `impl IntoCallback` parameter doesn't give them a type. Call-macro arguments and `callback(…)` don't need it | typed modifier parameters (`Callback<…>` only, so plain closures outside composables wouldn't be accepted) | low |
| D88 | (agent) Each memoized lambda's slot records a site id (a hash of its code), checked on lookup: a missed region group costs state, never correctness | trusting positional slots (a missed group handed `on_click = go_b` the `go_a` callback kept by another branch) | low |
| D89 | (agent) Callbacks take up to eight arguments | four (a fifth argument's closures failed to convert) | low |
| D90 | (agent) A focus request on a node without a focus target focuses the first one below it, as Compose's `FocusRequester`; Material's `TextField` merges its descendants' semantics, so its tag names the field | requiring the focus target itself (a tag on a decorated field's container couldn't take text input) | low |
| D91 | (agent) The runtime counts body runs per composable (by its restart closure's type name) while tracking is on, for tests (`recomposition_counts`) | no per-composable counts (only a total) | low |
| D92 | (agent) In the todo app, toggling an item re-runs the row's layout content (one `Checkbox`), not `TodoRow`'s body: content lambdas have no scope of their own (docs/03), so the read registers the layout invoking it | the sketch's expectation of exactly one `TodoRow` run | low |
| D93 | (agent) The desktop host renders with Skia's CPU raster backend and presents through `softbuffer`; GPU surfaces (Metal, Vulkan, Direct3D) are a later step behind the same `Renderer` | GPU surfaces first (a backend per platform before anything is on screen) | low |
| D94 | (agent) The Skia text measurer uses the system's fonts (with a list of preferred sans-serif families); tests that must not depend on fonts use the fixed-advance measurer | bundled fonts (font files to vendor into the repository) | low |
| D95 | (agent) A custom modifier element is an `Rc`, so a state change that rebuilds one (the checkbox's drawing) allocates; built-in elements (now including the 48 dp touch target, `minimum_touch_target`) don't, and modifiers keep six elements inline | built-in variants for every Material element (compose-ui would grow Material's drawing) | low |
| D96 | (agent) A value-based `BasicTextField` shows the application's `value`: an edit it doesn't take by the next frame is undone; the cursor starts at the start, moves by grapheme clusters, and a tap places it at once | trusting the node's own copy (a rejected or filtered edit stayed on screen) | low |
